### 3. Designing CLAUDE.md Correctly: The 2026 Architecture

**Source:** [Designing CLAUDE.md Correctly — Obvious Works](https://www.obviousworks.ch/en/designing-claude-md-right-the-2026-architecture-that-finally-makes-claude-code-work/)
**Time:** ~5 min read
**Published:** 2026

**Why it's relevant:** If you reuse Claude Code across consulting projects, a well-structured CLAUDE.md eliminates repetitive setup. Define your coding standards, preferred output formats, naming conventions, and project structure once — and Claude follows them consistently. The key insight: keep it lean (Claude ignores bloated files) and use hooks for anything that must happen 100% of the time.

**Key Takeaway:** Create a personal CLAUDE.md template for consulting projects with sections for: (1) output format preferences (e.g., "always use BCG-style executive summaries"), (2) data handling rules (e.g., "use pandas for tabular data, always show sample output"), and (3) file organization conventions. Move any mandatory rules (like "run linter after every edit") into hooks instead — CLAUDE.md is guidance (~80% compliance), hooks are deterministic (100%).

## Quick Win

**Set up a `/goal` for your next multi-step task.**

Instead of prompting Claude Code turn-by-turn for a complex analysis or deliverable, try this today:

```
/goal Analyze the dataset in data/sales_q1.csv: clean the data, identify top 3 trends,
create 4 publication-quality charts, and write a 1-page executive summary.
Stop when the summary and all charts are saved to output/.
```

Claude will work autonomously across multiple turns until the goal is met. You can monitor progress in Agent View (`claude --view`) while you work on something else. This alone can save 15-30 minutes of back-and-forth prompting on complex tasks.

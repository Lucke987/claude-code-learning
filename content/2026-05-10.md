## Resource 3: Claude Code May Releases — PostToolUse Output Replacement and Project Purge

**Source:** [Claude Code Changelog — Official Docs](https://code.claude.com/docs/en/changelog)
**Also:** [Claude Code Updates May 2026 — Releasebot](https://releasebot.io/updates/anthropic/claude-code)

**Also:** [Claude Code Releases — GitHub](https://github.com/anthropics/claude-code/releases)
**Time:** ~4 min read (changelog + Releasebot summary)
**Category:** Platform — Two Features That Directly Upgrade Your Pipeline

### Why This Is Relevant

While Managed Agents dominated the last three digests (dreaming, outcomes, multiagent), Claude Code itself shipped two features this week that directly improve your pipeline's daily operation: PostToolUse hooks can now replace tool output for *all* tools, and `project purge` gives you clean-state management for iterative development.

**1. PostToolUse `hookSpecificOutput.updatedToolOutput` — now for all tools**

Previously, PostToolUse hooks could only replace tool output for MCP tools. As of this week, `hookSpecificOutput.updatedToolOutput` works for *every* tool — including Bash, Read, Edit, and Write. This is a significant upgrade for your pipeline's validation layer.

**What this means for your 5-agent pipeline:**

Your PostToolUse hooks currently validate output (e.g., checking that JSON conforms to your API contract schema). But validation is binary: pass or fail. With `updatedToolOutput`, your hooks can now *transform* tool output before the agent sees it.

Practical use cases for your pipeline:

| Use Case | Before (Validation Only) | After (Output Replacement) |
|----------|-------------------------|---------------------------|
| Schema normalization | Hook rejects malformed JSON; agent retries | Hook fixes minor schema issues (missing optional fields, type coercion) and returns corrected output; agent proceeds |
| Sensitive data redaction | Hook blocks output containing credentials | Hook strips credentials and returns sanitized output; agent continues with safe data |
| Output enrichment | Hook can't add context | Hook appends metadata (timestamps, source cluster IDs) to tool output before the agent processes it |
| Cost-saving truncation | Large file reads consume context window | Hook truncates irrelevant sections of file reads, preserving context budget for the synthesis agent |

The last use case — context-budget-aware truncation — is particularly valuable for your pipeline. When a domain cluster agent reads a large config file, your hook can strip comments and whitespace before the output enters the context window, preserving budget for the cross-cluster synthesis that actually matters.

**2. `claude project purge` — clean-state management for iterative development**

New command: `claude project purge [path]` deletes all Claude Code state for a project — transcripts, tasks, file history, and config entry. Supports `--dry-run`, `-y/--yes`, `-i/--interactive`, and `--all`.

**Why this matters for your workflow:** After 41 digests of iterating on your `/reverse-engineer` skill, your project's accumulated state is substantial — hundreds of transcripts, task histories from abandoned approaches, file change records from 9 weeks of iteration. This state doesn't affect functionality, but it affects disk usage and can slow down features that index local history.

```bash
# Preview what would be cleaned up
claude project purge --dry-run

# Clean up state for a specific project path
claude project purge /path/to/isp-pipeline -y

# Nuclear option: all projects
claude project purge --all --interactive
```

**3. Other notable updates:**

- **`/skills` now has type-to-filter search:** Find your `/reverse-engineer` skill instantly in long lists without scrolling.
- **Memory leak fixes:** Image-heavy sessions, `/usage` on large transcript histories, and long-running tools all received memory leak patches. If your pipeline agents process architecture diagrams or screenshots, sessions will be more stable.
- **MCP server auto-retry:** MCP servers that hit transient startup errors now auto-retry up to 3 times. Combined with the `/mcp` tool count display from last week, your pipeline's MCP dependencies are more resilient and more visible.

### Key Takeaway

Add `hookSpecificOutput.updatedToolOutput` to your PostToolUse validation hook today. Start with the simplest use case: have your hook strip comments and trailing whitespace from large file reads before the output enters the agent's context window. This preserves context budget for cross-cluster synthesis without changing your agent prompts. Then run `claude project purge --dry-run` to see how much accumulated state your 9 weeks of iteration have produced — clean up what you don't need.

## Quick Win: Add Output Replacement to Your PostToolUse Validation Hook (5 min)

**Time: 5 minutes**

Your PostToolUse hook currently validates JSON output against your API contract schema. Upgrade it to *transform* output using the new `hookSpecificOutput.updatedToolOutput` capability.

**Step 1:** Open your PostToolUse hook configuration in `.claude/settings.json`.

**Step 2:** Modify your validation script to return `updatedToolOutput` when it can fix minor issues automatically:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Bash",
        "hook": {
          "type": "command",
          "command": "python3 .claude/hooks/validate_and_transform.py"
        }
      }
    ]
  }
}
```

**Step 3:** In your validation script, return the transformed output:

```python
import json, sys

# Read hook input from stdin
hook_input = json.load(sys.stdin)
tool_output = hook_input.get("tool_output", "")

# Example: strip comments and normalize whitespace for large outputs
if len(tool_output) > 5000:
    # Truncate to preserve context budget
    lines = tool_output.split("\n")
    filtered = [l for l in lines if not l.strip().startswith("#")]
    transformed = "\n".join(filtered)

    result = {
        "hookSpecificOutput": {
            "updatedToolOutput": transformed
        }
    }
    json.dump(result, sys.stdout)
```

**Why now:** Your 5-agent pipeline's context budget is its most constrained resource. Every line of comments, whitespace, and irrelevant config that enters a domain agent's context window is a line that can't be used for cross-cluster synthesis. Five minutes of hook setup now saves context budget on every pipeline run going forward — and you're using a feature that shipped this week, so you're ahead of the documentation.

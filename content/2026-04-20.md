## Resource 1: Opus 4.7 + xhigh Effort — Upgrade Your /reverse-engineer Pipeline for Better Architecture Analysis

**Source:** [Introducing Claude Opus 4.7 — Anthropic](https://www.anthropic.com/news/claude-opus-4-7)
**Also:** [Claude Opus 4.7: benchmarks, features, and migration guide — The AI Corner](https://www.the-ai-corner.com/p/claude-opus-4-7-guide-benchmarks-2026)
**Also:** [Claude Opus 4.7: Vision, Coding Gains, and xhigh Effort — ClaudeFast](https://claudefa.st/blog/models/claude-opus-4-7)
**Time:** ~5 min (skim the announcement + ClaudeFast practical guide)
**Category:** Model Upgrade — Direct Impact on Analysis Quality

### Why This Is Relevant

Opus 4.7 shipped April 16 and is the single biggest improvement to your architecture analysis quality since you started building the pipeline. Here's what matters for your ISP work:

**+13% coding benchmark improvement**: Architecture recovery is fundamentally a code comprehension task. Opus 4.7 scores 70% on CursorBench (up from 58% on 4.6) and solves 3x more production-grade tasks than its predecessor. For your `/reverse-engineer` skill analyzing 47 microservices, this means more accurate service boundary detection, better API flow tracing, and fewer false positives in coupling hotspot identification.

**xhigh effort — the sweet spot for architecture work**: Opus 4.7 introduces a new effort level between high and max. Here's the critical insight: **xhigh at 100K tokens scores 71%, already ahead of Opus 4.6's max at 200K tokens.** This means you get *better* analysis quality at *half* the token cost. For a 5-agent Agent Teams setup analyzing the full ISP codebase, this cuts your token bill roughly in half while improving results.

**The effort ladder for ISP tasks:**

| Task | Recommended Effort | Why |
|------|-------------------|-----|
| Quick file scan | high | Fast, cheap, good enough for surface-level |
| Service boundary analysis | xhigh | Best quality-to-cost ratio for deep comprehension |
| Cross-service flow tracing | xhigh | Complex reasoning without max's token overhead |
| Full architecture synthesis | max | Only when synthesizing findings across all 47 services |

**How to upgrade:**

```bash
# Check your version
claude --version

# Set xhigh as default effort
claude /effort  # Opens interactive slider — select xhigh

# Or set it in your project config
# .claude/settings.json
{
  "effort": "xhigh"
}
```

**Enhanced vision (3.75 megapixels)**: Opus 4.7 can see images at 2,576 pixels on the long edge. If you're including architecture diagrams, dependency graphs, or Mermaid renders in your analysis context, 4.7 reads them with substantially more accuracy. Feed your generated architecture diagrams back as visual context for verification.

### Key Takeaway

**Switch to Opus 4.7 with xhigh effort for all ISP architecture analysis.** You get better results than Opus 4.6 max at roughly half the token cost. Update your `/reverse-engineer` skill's model config and set xhigh as the default effort level. This is the highest-ROI change you can make to your pipeline this week — better quality, lower cost, zero workflow changes needed.

## Resource 2: /ultrareview — Multi-Agent Code Review That Validates Your Architecture Findings

**Source:** [Find bugs with ultrareview — Claude Code Docs](https://code.claude.com/docs/en/ultrareview)
**Also:** [Claude Code Ultra Review Tested: Multi-Agent Bug Hunting — Mejba Ahmed](https://www.mejba.me/blog/claude-code-ultra-review-tested)
**Also:** [Claude Code Ultrareview vs CodeRabbit vs Greptile — Rick Hightower, Medium](https://medium.com/@richardhightower/claude-code-ultrareview-vs-coderabbit-vs-greptile-94737b30ec1f)
**Time:** ~5 min (official docs + one hands-on review)
**Category:** Quality Assurance — Validate Architecture Analysis

### Why This Is Relevant

/ultrareview shipped April 16 alongside Opus 4.7, and it's the missing "quality assurance" piece in your ISP presentation. Here's why it matters for your workflow specifically:

**What it does:** When you run `/ultrareview`, Claude Code launches a fleet of reviewer agents (default 5, up to 20) in Anthropic's cloud infrastructure. Each agent reviews your changes from a different angle — one looks at logic errors, another at performance, another at security, another at architectural consistency. Findings are independently reproduced before being reported.

**Why this is your ISP quality story:**

Your current pipeline is: `/reverse-engineer` → analyze → document in CLAUDE.md. The gap is verification. How do you know the architecture analysis is accurate? How do you catch when Claude misidentifies a service boundary or misses a hidden dependency?

/ultrareview adds a verification layer:

1. Run `/reverse-engineer` on an ISP service cluster
2. Commit the architecture documentation and any refactoring recommendations
3. Run `/ultrareview` — the fleet of agents reviews your analysis artifacts against the actual code
4. Each reviewer independently checks: Do the documented service boundaries match the actual dependency graph? Are the identified coupling hotspots real? Did the analysis miss any critical cross-service calls?

**The cross-validation pattern:** Because each ultrareview agent has its own context window and perspective, they catch things that a single-pass analysis misses. Agent 1 might confirm your billing-provisioning coupling finding, while Agent 3 flags a hidden dependency between customer management and network operations that your initial analysis missed.

**Practical details:**

```bash
# Review your current branch against main
/ultrareview

# Review a specific PR
/ultrareview 1234

# It runs in the background — keep working while it reviews
# Typically takes 5-10 minutes
# Cost: $5-20 per run depending on changeset size
```

**For the ISP presentation:** *"Every architecture analysis is independently verified by a fleet of AI reviewers. Each reviewer examines the findings from a different angle and reproduces issues before flagging them. This is the AI equivalent of a peer review by 5 senior architects — running automatically on every analysis."*

### Key Takeaway

**Add /ultrareview as a verification step after every `/reverse-engineer` run.** It gives you independent, multi-angle validation of your architecture findings at $5-20 per review. For the ISP presentation, this is your quality assurance story: AI-generated analysis verified by AI-powered peer review, with findings independently reproduced before reporting. Run it once this week on your latest ISP analysis branch to see it in action.

**Category:** Workflow — Multi-Session Management for ISP

### Why This Is Relevant

The desktop app redesign shipped April 14 — the same day as your Anthropic Office Hours presentation. You may have missed it. Here's why it matters for your ISP Agent Teams workflow:

**Multi-session sidebar for Agent Teams visibility:**

When you run a 5-agent team analyzing ISP service clusters, you currently manage this from the CLI. The redesigned desktop app gives you a sidebar that shows every active session — including Agent Teams teammates — in one place. You can:

- See all 5 agents' progress at a glance (billing cluster agent, provisioning agent, etc.)
- Filter sessions by project or status
- Click into any agent's session to see its findings in real time
- Group sessions by project to separate ISP analysis from other work

This transforms Agent Teams from "launch and wait" to "monitor and steer."

**Drag-and-drop layout for analysis workflows:**

Arrange your workspace to match the architecture analysis flow:

```
┌─────────────────────┬─────────────────────┐
│ Agent Teams Sidebar  │ Main Analysis Chat   │
│ - Billing Agent ✓   │                      │
│ - Provisioning Agent │ [Active analysis     │
│ - Customer Mgmt ◌   │  session here]       │
│ - Network Ops ◌     │                      │
├─────────────────────┼─────────────────────┤
│ Integrated Terminal  │ Diff Viewer          │
```

**Side Chat for quick questions (Cmd+; / Ctrl+;):**

Mid-analysis, you often need to ask a quick question: "What's the typical latency for this API call?" or "Is this coupling pattern normal in Spring Boot?" Side Chat branches off your current session, pulls context from it, but doesn't pollute your main analysis thread. Perfect for ad-hoc questions during a long `/reverse-engineer` run.

**Integrated terminal and file editor:**

No more switching between the desktop app and your terminal. Run verification hooks, check git status, and make spot edits to CLAUDE.md — all within the same window as your analysis session.

### Key Takeaway

**Switch your ISP Agent Teams workflow from CLI-only to the redesigned desktop app.** The multi-session sidebar gives you real-time visibility into all 5 agents' progress, the drag-and-drop layout lets you build an analysis dashboard, and Side Chat keeps quick questions from derailing your main analysis.

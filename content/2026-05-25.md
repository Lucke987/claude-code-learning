## Today's Resources

### 1. Forcing Claude Code to TDD: An Agentic Red-Green-Refactor Loop

**URL:** https://alexop.dev/posts/custom-tdd-workflow-claude-code-vue/
**Time:** ~5 min read
**Category:** Code Quality & Verification

**Why it's relevant:** Claude Code has a structural tendency to write implementation first, then tests — which means the tests often just validate what Claude already wrote, not what you actually need. This article solves that with a multi-agent TDD workflow: one agent writes failing tests, a second agent writes only the code needed to make them pass, and a third refactors. Each agent gets a clean context window, preventing "context pollution" where implementation logic bleeds into test design. For consulting work where correctness matters (financial models, data pipelines, client-facing tools), this approach catches bugs that single-agent workflows miss entirely. The key insight: commit your failing tests *before* letting Claude implement — this gives you a safety net because the diff shows exactly what changed.

**Key Takeaway:** Never let Claude write tests and implementation in the same prompt. Split them: write tests first, commit, then implement. Claude will sometimes modify tests to make them pass rather than fixing the actual code — committing the tests first prevents this.

### 2. Why I Shrunk Claude Code's Context Window Back to 200k

**URL:** https://albertsikkema.com/ai/development/tools/2026/04/23/smaller-context-window-better-claude-code.html
**Time:** ~5 min read
**Category:** Performance Optimization

**Why it's relevant:** This is counterintuitive but backed by real experience: using a smaller context window (200k instead of 1M) actually produces *better* results. The reason is compaction quality — when a 1M window compacts, it must summarize away ~400,000 tokens, losing massive detail. A 200k window only discards ~80,000 tokens, resulting in 5x less information loss. The author's workflow separates each development phase (research, planning, building) into its own session with an orchestrator that launches separate Claude Code instances. For a consultant juggling multiple workstreams, this "many short sessions" approach maps naturally to how you already switch between client projects. Bonus: smaller context windows = lower per-session cost.

**Key Takeaway:** More context isn't always better. Try splitting complex tasks into focused sessions (research → plan → build) rather than cramming everything into one long session. Your compaction summaries will be more accurate, and Claude will stay sharper longer.

### 3. How to Use the /compact Command to Prevent Context Rot

**URL:** https://www.mindstudio.ai/blog/claude-code-compact-command-context-management
**Time:** ~4 min read
**Category:** Session Management

**Why it's relevant:** "Context rot" is when Claude starts forgetting earlier instructions or making mistakes because the context window is nearly full. Most users wait for auto-compaction to trigger at ~95% capacity — by then, quality has already degraded. This article explains the /compact command and when to use it proactively. The critical timing insight: compact at 60% capacity, not 95%. At 60%, Claude still has enough working memory to produce a high-quality summary. At 95%, the summary itself is rushed and lossy. Combined with /clear between unrelated tasks, this keeps every session sharp. The article also reinforces a rule from previous digests: anything Claude must *always* remember belongs in CLAUDE.md, not in conversation context — compaction will eventually lose it.

**Key Takeaway:** Run `/compact` proactively when you notice a session getting long — don't wait for auto-compaction. And use `/clear` when switching between unrelated tasks in the same session. These two habits alone prevent most "Claude got confused" moments.

## Quick Win: The 60% Compaction Rule

**Apply this in your next session (30 seconds):**

When you're in a long Claude Code session and notice things getting complex, check the context indicator in the status bar. If it's approaching 60%, run:

```
/compact Focus on: [the specific task you're working on right now]
```

Adding a focus hint to `/compact` tells Claude what to prioritize in the summary. For example:

- `/compact Focus on: the data cleaning pipeline we're building for client X`
- `/compact Focus on: the API integration and the error handling patterns we decided on`

This produces a dramatically better summary than generic auto-compaction, because Claude knows which details matter to you. You'll keep full fidelity on your active task while gracefully dropping the exploratory tangents that filled up context earlier.

**Why this works:** Generic compaction treats all conversation equally. Focused compaction preserves the 20% of context that drives 80% of your current task's quality.

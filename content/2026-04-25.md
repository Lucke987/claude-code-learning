## 1. Claude Code Routines: Automate Recurring Tasks in the Cloud

**Source:** [Introducing routines in Claude Code - Anthropic Blog](https://claude.com/blog/introducing-routines-in-claude-code)
**Time estimate:** ~5 min read
**Published:** April 14, 2026

### Why this matters for you

Routines are scheduled Claude Code automations that run on cloud infrastructure - your laptop doesn't need to be open. You configure a prompt, connect a repo, and set a trigger: scheduled (daily/weekly), API call, or GitHub event.

**Direct application to your work:**
- Schedule a nightly routine to pull updated data from a shared repo, run your analysis script, and commit refreshed outputs
- Trigger a routine on PR events to auto-review code changes against your team's standards
- Set up weekly report generation that runs every Monday at 7am before your team standup

### Key Takeaway

Create your first routine with `/schedule` in any Claude Code session. Start simple: `/schedule daily PR review at 9am`. The prompt is the most important part - write it as if briefing a colleague who won't be able to ask follow-up questions.

This article covers how Claude Code workflows have evolved - from manual context management to persistent project memory and structured execution. The split-and-merge pattern is particularly relevant: Claude fans out work to up to 10 sub-agents simultaneously and merges results in a single terminal session.

**Direct application to your work:**
- Use the split-and-merge pattern when analyzing multiple data sources simultaneously (e.g., market sizing across 5 geographies)
- Leverage persistent project memory via CLAUDE.md so your analysis context carries across sessions instead of re-explaining your project every time
- Structure complex deliverables as sequential workflows: data pull -> analysis -> visualization -> deck generation

### Key Takeaway

If you're not using a CLAUDE.md file in your project repos, start today. It gives Claude persistent context about your project structure, coding conventions, and analysis approach - eliminating the "cold start" problem at the beginning of each session.

## Quick Win: Set Up CLAUDE.md for Your Current Project

**Time: 2 minutes**

In your current working repo, run:

```
/init
```

This creates a CLAUDE.md file that documents your codebase. Then add 3-5 lines about your project context:

```markdown
## Project Context
- This is a [market analysis / due diligence / cost optimization] project for [industry]
- Key data sources: [list Excel files or data directories]
- Final deliverable: PowerPoint deck following BCG template in /templates/
- Python environment: use pandas for data, python-pptx for slides
```

Every future Claude Code session in this repo will automatically read this file, giving Claude full context without you having to re-explain. This alone can save 5-10 minutes per session.

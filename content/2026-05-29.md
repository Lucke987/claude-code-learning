### 3. The Session Retro Habit: How to Make Claude Code Smarter Over Time

**Source:** [How I Continually Improve My Claude Code — Towards Data Science](https://towardsdatascience.com/how-i-continually-improve-my-claude-code/)
**Time:** ~3 min skim (focus on the retro section)
**Category:** Workflow optimization

**Why it matters for you:** As a daily user, small compounding improvements matter enormously. The core idea: at the end of each session, ask Claude *"What did you learn during this session?"* and route each learning to the right place — project rules go in CLAUDE.md, reusable patterns become Skills, architectural decisions go in ADRs. This turns every session into training data for the next one.

Bonus: there's a dedicated [Retro Skill on MCP Market](https://mcpmarket.com/tools/skills/claude-session-retrospective) that automates this — it analyzes your completed tasks, audits your `.claude` directory settings, and suggests config optimizations.

**Key Takeaway:** Add one line to your end-of-day routine: before closing Claude Code, type *"What did you learn this session that should go into CLAUDE.md?"* — it takes 30 seconds and compounds daily.

## Quick Win

**Apply this to your next session today:**

Before starting your next Claude Code session, run `/init` in your project directory if you haven't already. It auto-generates a CLAUDE.md by scanning your project's folder structure, build system, test framework, and code patterns. Then **ruthlessly prune it** — if your CLAUDE.md is too long, Claude ignores half of it. The rule of thumb from the [official best practices](https://code.claude.com/docs/en/best-practices): if Claude already does something correctly without the instruction, delete it from CLAUDE.md or convert it to a hook (which enforces the rule 100% of the time vs. ~70-80% for CLAUDE.md).

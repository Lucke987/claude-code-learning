### 3. CLAUDE.md Best Practices & Custom Commands That Actually Work
**Source:** [How I use Claude Code (+ my best tips) — Builder.io](https://www.builder.io/blog/claude-code)
**Time:** ~6 min read

**Why it's relevant:** If you're not using a `CLAUDE.md` file per project, you're leaving the single highest-impact productivity lever untouched. For consulting, this means each client engagement can have its own context: naming conventions, data schemas, preferred output formats, and domain-specific terminology. Custom commands (`.claude/commands/*.md`) let you create reusable prompts — think `/data-profile` to auto-analyze a new dataset, or `/exec-summary` to structure findings into a pyramid-principle narrative.

**Key Takeaway:** Create a `CLAUDE.md` in your project root with 3 things: (1) what the project is about in 2-3 sentences, (2) the tech stack and key file locations, (3) output conventions (e.g., "always use snake_case for Python, format tables as markdown"). Keep it under 150 lines — every unnecessary line dilutes the ones that matter. CLAUDE.md is advisory (~80% compliance); for must-happen rules, use hooks instead.

## Quick Win: Set Up a Data Profiling Custom Command

Create this file in any project where you work with data:

```
mkdir -p .claude/commands
```

Then create `.claude/commands/data-profile.md`:

```markdown
Analyze the dataset at $ARGUMENTS:

1. Show shape, dtypes, and memory usage
2. Summary statistics for all numeric columns
3. Missing value counts and percentages
4. Flag potential outliers (values beyond 3 standard deviations)
5. Show value counts for categorical columns with fewer than 20 unique values
6. Suggest 3 data quality issues to investigate

Output as a clean markdown report I can paste into a client deck.
```

Now in any Claude Code session, type `/data-profile path/to/data.csv` and get an instant, structured data quality report. This alone can save 30+ minutes per new dataset — time you'd otherwise spend writing one-off pandas scripts.

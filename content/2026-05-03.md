## Resource 3: Parallel Development with Git Worktrees — 4x Your Pipeline Throughput

**Source:** [The Claude Code Git Worktree Pattern: A Primer for Builders — MindStudio](https://www.mindstudio.ai/blog/what-is-claude-code-git-worktree-pattern-parallel-feature-branches)
**Also:** [Mastering Parallel Agent Development in Claude Code — Claude Lab](https://claudelab.net/en/articles/claude-code/claude-code-parallel-development-mastery)
**Also:** [Parallel Vibe Coding: Using Git Worktrees with Claude Code — Dan Does Code](https://www.dandoescode.com/blog/parallel-vibe-coding-with-git-worktrees)
**Also:** [Claude Code Worktrees: Parallel Sessions Without Conflicts — Claudefast](https://claudefa.st/blog/guide/development/worktree-guide)
**Time:** ~5 min read (Dan Does Code — the most practical walkthrough)
**Category:** Operations — From Serial to Parallel Pipeline Execution

### Why This Is Relevant

Your ISP pipeline analyzes 4 domain clusters (billing, provisioning, network, customer) with 4 teammate agents coordinated by a lead. Agent Teams handles the multi-agent coordination, but the agents share a single workspace — file writes from one agent can collide with another's reads. Git worktrees solve this by giving each agent its own isolated checkout of the repository, enabling true parallel execution.

**How worktrees work in Claude Code:**

```bash
# Each agent gets its own worktree — a separate directory
# with its own branch, sharing the same .git history
git worktree add ../isp-billing billing-analysis
git worktree add ../isp-provisioning provisioning-analysis
git worktree add ../isp-network network-analysis
git worktree add ../isp-customer customer-analysis

# Run Claude Code in each worktree simultaneously
# No file conflicts — each agent writes to its own directory
```

**Claude Code has built-in worktree support.** You don't need to manage worktrees manually. Two ways to use it:

1. **Agent Teams with isolation:** Add `isolation: worktree` to a custom subagent's frontmatter, and each teammate automatically gets its own worktree. No manual setup.

2. **CLI flag:** Run `claude -w` to launch a Claude Code session in a new worktree. Combine with headless mode: `claude -p "Analyze billing cluster" -w` runs the analysis in an isolated checkout.

**The throughput impact for your ISP pipeline:**

| Execution Mode | Cluster Analysis | Total Time (Est.) | Conflicts |
|---------------|-----------------|-------------------|-----------|
| Serial (current) | One at a time | 4 × T | None |
| Agent Teams (shared workspace) | Parallel but shared files | ~T + overhead | Possible |
| **Worktree isolation** | **True parallel, isolated** | **~T (wall clock)** | **None** |

If each cluster analysis takes time T, worktree isolation reduces your total pipeline time from approximately 4T to approximately T — the clusters run simultaneously with zero file-conflict risk.

**Practical limits:** 2–4 parallel sessions are recommended. Beyond that, API rate limits and review overhead diminish returns. For your 4-cluster pipeline, this is the sweet spot — one worktree per cluster, all running in parallel.

**How this integrates with your existing setup:**

- **Routines:** Schedule a Routine that spawns 4 worktree-isolated agents — one per cluster — then merges results
- **Observability:** Each worktree agent produces its own Langfuse/Opik trace, filterable by cluster
- **Cost:** Same total token cost as serial execution — worktrees don't add token overhead, only reduce wall-clock time

### Key Takeaway

On your next local Agent Teams run, add `isolation: worktree` to your teammate agent configurations. Watch the 4 domain clusters run in parallel without the file-collision risk you've been working around. If the total pipeline time drops from ~4T to ~T, you've validated a 4x throughput improvement with a one-line configuration change — and you have a concrete performance metric for your presentation.
